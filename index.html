Chapter 2: Getting Started (Lect. 2, 4)

Exercise 2.2-2

Selection Sort: pseudocodice, invariante e complessita

Consider sorting \(n\) numbers stored in array \(A[1:n]\) by first finding the smallest element of \(A[1:n]\) and exchanging it with the element in \(A[1]\). Then find the smallest element of \(A[2:n]\), and exchange it with \(A[2]\). Then find the smallest element of \(A[3:n]\), and exchange it with \(A[3]\). Continue in this manner for the first \(n - 1\) elements of \(A\). Write pseudocode for this algorithm, which is known as selection sort. What loop invariant does this algorithm maintain? Why does it need to run for only the first \(n - 1\) elements, rather than for all \(n\) elements? Give the worst-case running time of selection sort in \(\Theta\)-notation. Is the best-case running time any better?

Mostra soluzione ufficiale (Cormen, p. 2-1) 
SELECTION-SORT(A, n)
for i = 1 to n - 1
    smallest = i
    for j = i + 1 to n
        if A[j] < A[smallest]
            smallest = j
    exchange A[i] with A[smallest]

The algorithm maintains the loop invariant that at the start of each iteration of the outer for loop, the subarray \(A[1:i - 1]\) consists of the \(i - 1\) smallest elements in the array \(A[1:n]\), and this subarray is in sorted order. After the first \(n - 1\) elements, the subarray \(A[1:n - 1]\) contains the smallest \(n - 1\) elements, sorted, and therefore element \(A[n]\) must be the largest element.

The running time of the algorithm is \(\Theta(n^2)\) for all cases.

Exercise 2.2-4

Modificare un algoritmo per avere un buon caso migliore

How can you modify any sorting algorithm to have a good best-case running time?

Mostra soluzione ufficiale (Cormen, p. 2-1)

Modify the algorithm so that it first checks the input array to see whether it is already sorted, taking \(\Theta(n)\) time for an \(n\)-element array. If the array is already sorted, then the algorithm is done. Otherwise, sort the array as usual. The best-case running time is generally not a good measure of an algorithm's efficiency.

Exercise 2.3-6

Binary Search: pseudocodice iterativo/ricorsivo e tempo \(\Theta(\lg n)\)

Referring back to the searching problem, observe that if the subarray being searched is already sorted, the searching algorithm can check the midpoint of the subarray against \(x\) and eliminate half of the subarray from further consideration. The binary search algorithm repeats this procedure, halving the size of the remaining portion of the subarray each time. Write pseudocode, either iterative or recursive, for binary search. Argue that the worst-case running time of binary search is \(\Theta(\lg n)\).

Mostra soluzione ufficiale (Cormen, p. 2-1 / 2-2)

Procedure BINARY-SEARCH takes a sorted array \(A\), a value \(x\), and a range \([low : high]\). The initial call to either version should have the parameters \(A, x, 1, n\).

ITERATIVE-BINARY-SEARCH(A, x, low, high)
while low <= high
    mid = floor((low + high) / 2)
    if x == A[mid]
        return mid
    elseif x > A[mid]
        low = mid + 1
    else high = mid - 1
return NIL

RECURSIVE-BINARY-SEARCH(A, x, low, high)
if low > high
    return NIL
mid = floor((low + high) / 2)
if x == A[mid]
    return mid
elseif x > A[mid]
    return RECURSIVE-BINARY-SEARCH(A, x, mid + 1, high)
else return RECURSIVE-BINARY-SEARCH(A, x, low, mid - 1)

Both procedures terminate unsuccessfully when the range is empty (\(low > high\)) and terminate successfully if \(x\) is found. Based on the comparison of \(x\) to the middle element, the search continues with the range halved. The recurrence is therefore \(T(n) = T(n/2) + \Theta(1)\), whose solution is \(T(n) = \Theta(\lg n)\).

Problem 2-4

Inversions: conteggio in \(\Theta(n \lg n)\) tramite Merge Sort

Let \(A[1:n]\) be an array of \(n\) distinct numbers. If \(i < j\) and \(A[i] > A[j]\), then the pair \((i, j)\) is called an inversion of \(A\).

  1. List the five inversions of the array \(\langle 2, 3, 8, 6, 1 \rangle\).
  2. What array with elements from the set \(\{1, 2, \dots, n\}\) has the most inversions? How many does it have?
  3. What is the relationship between the running time of insertion sort and the number of inversions in the input array? Justify your answer.
  4. Give an algorithm that determines the number of inversions in any permutation on \(n\) elements in \(\Theta(n \lg n)\) worst-case time. (Hint: Modify merge sort.)
Mostra soluzione ufficiale (Cormen, p. 2-2 / 2-4)

a. The inversions are \((1, 5), (2, 5), (3, 4), (3, 5), (4, 5)\) (specified by indices, not values).

b. The array \(\langle n, n-1, n-2, \dots, 2, 1 \rangle\) has the most inversions. For all \(1 \le i < j \le n\), \((i, j)\) is an inversion, giving \(\binom{n}{2} = n(n-1)/2\) inversions.

c. Suppose \(A\) starts with an inversion \((k, i)\) where \(k < i\) and \(A[k] > A[i]\). When the outer for loop sets \(key = A[i]\), the value originally in \(A[k]\) sits at some \(A[j]\) with \(1 \le j < i\). An iteration of the while loop moves \(A[j]\) one position right, and inserting \(key\) to its left eliminates that inversion. Because the while loop moves only elements greater than \(key\), each iteration corresponds to eliminating exactly one inversion.

d. Define a merge-inversion as a situation in MERGE where \(x \in L\) and \(y \in R\) satisfy \(x > y\). There is a one-to-one correspondence between inversions of \(A\) and merge-inversions across the execution of merge sort. Whenever \(z = L[i]\) and \(y = R[j]\) are exposed with \(z > y\), \(y\) forms merge-inversions with all \(n_L - i\) remaining elements of \(L\).

MERGE-INVERSIONS(A, p, q, r)
n_L = q - p + 1
n_R = r - q
let L[0 : n_L - 1] and R[0 : n_R - 1] be new arrays
for i = 0 to n_L - 1
    L[i] = A[p + i - 1]
for j = 0 to n_R - 1
    R[j] = A[q + j]
i = 0; j = 0; k = p; inversions = 0
while i < n_L and j < n_R
    if L[i] <= R[j]
        A[k] = L[i]
        i = i + 1
    else
        inversions = inversions + n_L - i
        A[k] = R[j]
        j = j + 1
    k = k + 1
while i < n_L
    A[k] = L[i]; i = i + 1; k = k + 1
while j < n_R
    A[k] = R[j]; j = j + 1; k = k + 1
return inversions

COUNT-INVERSIONS(A, p, r)
inversions = 0
if p < r
    q = floor((p + r) / 2)
    inversions = inversions + COUNT-INVERSIONS(A, p, q)
    inversions = inversions + COUNT-INVERSIONS(A, q + 1, r)
    inversions = inversions + MERGE-INVERSIONS(A, p, q, r)
return inversions

Initial call: COUNT-INVERSIONS(A, 1, n). Only constant work is added per recursive call and loop step, so total time is \(\Theta(n \lg n)\).

Nota errata nel PDF di Cormen (p. 2-4): nel PDF originale la riga inversions = inversions + n_L - i compare per errore nel ramo if L[i] <= R[j] invece che nel ramo else (dove \(L[i] > R[j]\)). Sopra e riportata la collocazione corretta coerente con la dimostrazione dello stesso PDF.

Chapter 3: Characterizing Running Times (Lect. 3)

Exercise 3.2-2

Perche "at least \(O(n^2)\)" e privo di significato

Explain why the statement, "The running time of algorithm \(A\) is at least \(O(n^2)\)," is meaningless.

Mostra soluzione ufficiale (Cormen, p. 3-1)

Since \(O\)-notation provides only an upper bound, and not a tight bound, the statement is saying that the running time of algorithm \(A\) is at least a function whose rate of growth is at most \(n^2\). Because the constant function \(0\) (or \(1\)) is \(O(n^2)\), this says nothing useful about either an upper or a lower bound on the running time.

Exercise 3.2-3

Confronto asintotico di \(2^{n+1}\) e \(2^{2n}\) rispetto a \(O(2^n)\)

Is \(2^{n + 1} = O(2^n)\)? Is \(2^{2n} = O(2^n)\)?

Mostra soluzione ufficiale (Cormen, p. 3-1)

\(2^{n+1} = O(2^n)\), but \(2^{2n} \ne O(2^n)\).

To show that \(2^{n+1} = O(2^n)\), we must find constants \(c, n_0 > 0\) such that \(0 \le 2^{n+1} \le c \cdot 2^n\) for all \(n \ge n_0\). Since \(2^{n+1} = 2 \cdot 2^n\) for all \(n\), we satisfy the definition with \(c = 2\) and \(n_0 = 1\).

To show that \(2^{2n} \ne O(2^n)\), assume there exist constants \(c, n_0 > 0\) such that \(0 \le 2^{2n} \le c \cdot 2^n\) for all \(n \ge n_0\). Then \(2^{2n} = 2^n \cdot 2^n \le c \cdot 2^n \implies 2^n \le c\). No constant is greater than all \(2^n\), yielding a contradiction.

Exercise 3.3-5

Limitatezza polinomiale di \(\lceil \lg n \rceil!\) e \(\lceil \lg \lg n \rceil!\)

Is the function \(\lceil \lg n \rceil!\) polynomially bounded? Is the function \(\lceil \lg \lg n \rceil!\) polynomially bounded?

Mostra soluzione ufficiale (Cormen, p. 3-1 / 3-2)

\(\lceil \lg n \rceil!\) is not polynomially bounded, while \(\lceil \lg \lg n \rceil!\) is polynomially bounded.

First note that \(f(n)\) is polynomially bounded if and only if \(\lg f(n) = O(\lg n)\):

  • If \(0 \le f(n) \le c n^k\) for \(n \ge n_0\) (with WLOG \(c \ge 1, n_0 \ge 2\)), then \(\lg f(n) \le \lg c + k \lg n \le (\lg c + k) \lg n = O(\lg n)\).
  • Conversely, if \(0 \le \lg f(n) \le c \lg n\) for \(n \ge n_0\), then \(0 \le f(n) = 2^{\lg f(n)} \le 2^{c \lg n} = n^c\).

Using \(\lg(n!) = \Theta(n \lg n)\) and \(\lceil \lg n \rceil = \Theta(\lg n)\):

\[ \lg(\lceil \lg n \rceil!) = \Theta(\lceil \lg n \rceil \lg \lceil \lg n \rceil) = \Theta((\lg n)(\lg \lg n)) = \omega(\lg n) \]

so \(\lg(\lceil \lg n \rceil!) \ne O(\lg n)\) and \(\lceil \lg n \rceil!\) is not polynomially bounded. For the second function:

\[ \lg(\lceil \lg \lg n \rceil!) = \Theta((\lg \lg n)(\lg \lg \lg n)) = o((\lg \lg n)^2) = o(\lg^2(\lg n)) = o(\lg n) \]

using the fact that \(\lg^b m = o(m^a)\) for \(a, b > 0\) with \(m = \lg n, b = 2, a = 1\). Hence \(\lg(\lceil \lg \lg n \rceil!) = O(\lg n)\), and \(\lceil \lg \lg n \rceil!\) is polynomially bounded.

Chapter 4: Divide-and-Conquer (Lect. 3, 4)

Exercise 4.4-4

Albero di ricorsione e sostituzione per \(T(n) = T(\alpha n) + T((1 - \alpha)n) + cn\)

Use a recursion tree to give an asymptotically tight solution to the recurrence

\[T(n) = T(\alpha n) + T((1 - \alpha)n) + cn\]

where \(\alpha\) is a constant in the range \(0 < \alpha < 1\), and \(c > 0\) is also a constant.

Mostra soluzione ufficiale (Cormen, p. 4-1 / 4-2)

Without loss of generality, let \(\alpha \ge 1 - \alpha\), so that \(0 < 1 - \alpha \le 1/2\) and \(1/2 \le \alpha < 1\).

The recursion tree is full for \(\log_{1/(1-\alpha)} n\) levels, each contributing \(cn\), so we guess \(\Omega(n \log_{1/(1-\alpha)} n) = \Omega(n \lg n)\). It has \(\log_{1/\alpha} n\) levels, each contributing \(\le cn\), so we guess \(O(n \log_{1/\alpha} n) = O(n \lg n)\).

Substitution proof (upper bound): Show \(T(n) \le d n \lg n\) for a constant \(d > 0\):

\[ \begin{aligned} T(n) &= T(\alpha n) + T((1 - \alpha)n) + cn \\ &\le d\alpha n \lg(\alpha n) + d(1 - \alpha)n \lg((1 - \alpha)n) + cn \\ &= d n \lg n + d n\bigl(\alpha \lg \alpha + (1 - \alpha)\lg(1 - \alpha)\bigr) + cn \\ &\le d n \lg n \end{aligned} \]

provided \(d\bigl(\alpha \lg \alpha + (1 - \alpha)\lg(1 - \alpha)\bigr) \le -c\). Since \(\lg \alpha < 0\) and \(\lg(1 - \alpha) < 0\), dividing reverses the inequality:

\[d \ge \frac{c}{-\alpha \lg \alpha - (1 - \alpha)\lg(1 - \alpha)}\]

Lower bound: Replacing \(\le\) with \(\ge\) gives the matching condition \(0 < d \le \frac{c}{-\alpha \lg \alpha - (1 - \alpha)\lg(1 - \alpha)}\). Therefore \(T(n) = \Theta(n \lg n)\).

Chapter 11: Hash Tables (Lect. 8)

Exercise 11.2-1

Numero atteso di collisioni con hashing uniforme

Suppose we use a random hash function \(h\) to hash \(n\) distinct keys into an array \(T\) of length \(m\). Assuming independent uniform hashing, what is the expected number of collisions? More precisely, what is the expected cardinality of \(\{\{k, l\} : k \ne l \text{ and } h(k) = h(l)\}\)?

Mostra soluzione ufficiale (Cormen, p. 11-1)

For each unordered pair of distinct keys \(k, l\) (\(k \ne l\)), define the indicator random variable \(X_{kl} = \mathrm{I}\{h(k) = h(l)\}\). Under independent uniform hashing, \(\Pr\{X_{kl} = 1\} = 1/m\), so \(\mathrm{E}[X_{kl}] = 1/m\).

Let \(Y = \sum_{k \ne l} X_{kl}\) be the total number of collisions. By linearity of expectation:

\[ \mathrm{E}[Y] = \mathrm{E}\left[\sum_{k \ne l} X_{kl}\right] = \sum_{k \ne l} \mathrm{E}[X_{kl}] = \binom{n}{2} \frac{1}{m} = \frac{n(n - 1)}{2m} \]
Exercise 11.2-4

Free list interna alla tabella hash in tempo atteso \(O(1)\)

Suggest how to allocate and deallocate storage for elements within the hash table itself by linking all unused slots into a free list. Assume that one slot can store a flag and either one element plus a pointer or two pointers. All dictionary and free-list operations should run in \(O(1)\) expected time. Does the free list need to be doubly linked, or does a singly linked free list suffice?

Mostra soluzione ufficiale (Cormen, p. 11-1 / 11-2)

The flag in each slot indicates whether the slot is free. A free slot belongs to a doubly linked free list (storing two pointers). A used slot stores an element and a pointer (possibly NIL) to the next element in its chain.

  • Insertion:
    • If the element hashes to a free slot, remove that slot from the doubly linked free list in \(O(1)\) time and store the element with a NIL pointer.
    • If it hashes to a used slot \(j\) whose occupant \(x\) also hashes to \(j\), allocate a free slot from the head of the free list and prepend it to \(j\)'s chain.
    • If occupant \(x\) belongs to another slot's chain, allocate a free slot, move \(x\) and its pointer there, update the predecessor pointing to \(j\) (found by scanning \(x\)'s chain), and insert the new element in \(j\).
  • Deletion (element \(x\) hashing to slot \(j\)):
    • If \(x\) is the only element in \(j\), free \(j\) and push it onto the head of the free list.
    • If \(x\) is in \(j\) with a chain behind it, move the next node into \(j\) and free that node's old slot.
    • If \(x\) is later in the chain, splice it out and push its slot onto the free list.
  • Searching: Check slot \(h(k)\) and follow chain pointers.

Since all elements live inside the table, \(\alpha \le 1\), so chain traversals take \(O(1 + \alpha) = O(1)\) expected time. The free list must be doubly linked so removing an arbitrary slot (the one hashed to) takes \(O(1)\) time.

Problem 11-3

Slot-size bound for chaining: \(\mathrm{E}[M] = O(\lg n / \lg \lg n)\)

Suppose that we have a hash table with \(n\) slots, with collisions resolved by chaining, and suppose that \(n\) keys are inserted into the table. Each key is equally likely to be hashed to each slot. Let \(M\) be the maximum number of keys in any slot after all the keys have been inserted. Prove an \(O(\lg n / \lg \lg n)\) upper bound on \(\mathrm{E}[M]\).

  1. Argue that the probability \(Q_k\) that exactly \(k\) keys hash to a particular slot is \(Q_k = \left(\frac{1}{n}\right)^k \left(1 - \frac{1}{n}\right)^{n - k} \binom{n}{k}\).
  2. Let \(P_k = \Pr\{M = k\}\). Show that \(P_k \le n Q_k\).
  3. Show that \(Q_k < e^k / k^k\).
  4. Show that there exists a constant \(c > 1\) such that \(Q_{k_0} < 1/n^3\) for \(k_0 = c \lg n / \lg \lg n\). Conclude that \(P_k < 1/n^2\) for \(k \ge k_0\).
  5. Argue that \(\mathrm{E}[M] \le \Pr\{M > k_0\} \cdot n + \Pr\{M \le k_0\} \cdot k_0\), and conclude that \(\mathrm{E}[M] = O(\lg n / \lg \lg n)\).
Mostra soluzione ufficiale (Cormen, p. 11-2 / 11-5)

a. A specific set of \(k\) keys lands in the target slot and the remaining \(n-k\) land elsewhere with probability \((1/n)^k (1 - 1/n)^{n-k}\). Multiplying by \(\binom{n}{k}\) choices of \(k\) keys yields \(Q_k\).

b. Let \(A_i\) be the event that slot \(i\) receives exactly \(k\) keys (\(\Pr\{A_i\} = Q_k\)). By union bound:

\[P_k = \Pr\{M = k\} \le \Pr\{A_1 \cup \dots \cup A_n\} \le \sum_{i=1}^n \Pr\{A_i\} = n Q_k\]

c. Since \((1 - 1/n)^{n-k} \le 1\), \(n! / (n-k)! < n^k\), and \(k! > (k/e)^k\):

\[Q_k = \left(\frac{1}{n}\right)^k \left(1 - \frac{1}{n}\right)^{n-k} \frac{n!}{k!(n-k)!} \le \frac{n!}{n^k k!(n-k)!} < \frac{1}{k!} < \frac{e^k}{k^k}\]

d. For \(n \ge 3\), it suffices that \(e^{k_0}/k_0^{k_0} < 1/n^3\), i.e. \(3 \lg n < k_0(\lg k_0 - \lg e)\). Substituting \(k_0 = c \lg n / \lg \lg n\) and dividing by \(\lg n\) gives:

\[3 < c \left(1 + \frac{\lg c - \lg e}{\lg \lg n} - \frac{\lg \lg \lg n}{\lg \lg n}\right)\]

The parenthesized factor tends to \(1\) as \(n \to \infty\), so it is \(\ge 1/2\) for \(n \ge n_0\); picking \(c > 6\) (and large enough for the finite range \(3 \le n < n_0\) and \(k_0 > 3 > e\)) makes \(e^k / k^k\) decreasing for \(k \ge k_0\), hence \(Q_k \le Q_{k_0} < 1/n^3\) and \(P_k \le n Q_k < 1/n^2\).

e. Splitting the sum for \(\mathrm{E}[M] = \sum_{k=0}^{n} k \Pr\{M = k\}\) at \(k_0\) bounds \(k \le k_0\) on the first part and \(k \le n\) on the second, giving \(\mathrm{E}[M] \le k_0 \Pr\{M \le k_0\} + n \Pr\{M > k_0\}\). Since \(\Pr\{M > k_0\} = \sum_{k=k_0+1}^n P_k < n \cdot (1/n^2) = 1/n\), we obtain \(\mathrm{E}[M] \le k_0 \cdot 1 + n \cdot (1/n) = k_0 + 1 = O(\lg n / \lg \lg n)\).

Chapter 12: Binary Search Trees (Lect. 7)

Exercise 12.1-2

Proprieta BST vs Min-Heap e stampa ordinata in \(O(n)\)

What is the difference between the binary-search-tree property and the min-heap property? Can the min-heap property be used to print out the keys of an \(n\)-node tree in sorted order in \(O(n)\) time? Show how, or explain why not.

Mostra soluzione ufficiale (Cormen, p. 12-1)

In a max-heap (or min-heap), a node's key is \(\ge\) (or \(\le\)) both of its children's keys. In a binary search tree, a node's key is \(\ge\) its left child's key and \(\le\) its right child's key.

The heap property does not help print keys in sorted order in \(O(n)\) time because it does not tell which subtree contains the next element to print. Moreover, if the heap property allowed printing keys in sorted order in \(O(n)\) time, we would have an \(O(n)\) comparison sort (since building a heap takes \(O(n)\) time), contradicting the \(\Omega(n \lg n)\) lower bound for comparison sorting (Theorem 8.1).

Exercise 12.2-7

Visita inorder con TREE-MINIMUM + \(n - 1\) chiamate a TREE-SUCCESSOR in \(\Theta(n)\)

An alternative method of performing an inorder tree walk of an \(n\)-node binary search tree finds the minimum element in the tree by calling TREE-MINIMUM and then making \(n - 1\) calls to TREE-SUCCESSOR. Prove that this algorithm runs in \(\Theta(n)\) time.

Mostra soluzione ufficiale (Cormen, p. 12-1 / 12-2)

Calling TREE-MINIMUM followed by \(n - 1\) calls to TREE-SUCCESSOR produces the exact same inorder sequence as INORDER-TREE-WALK. It takes \(\Omega(n)\) time simply for the \(n\) procedure calls.

To show \(O(n)\) time, we prove that each of the \(n - 1\) tree edges \((u, v)\) (where \(u\) is the parent of \(v\)) is traversed at most twice: once downward (in TREE-MINIMUM) and once upward (in TREE-SUCCESSOR when no right subtree exists):

  • If \(v\) is \(u\)'s left child: edge \((u, v)\) is traversed downward before printing \(u\)'s left subtree, and upward once when calling TREE-SUCCESSOR on the maximum node of \(v\)'s subtree to reach \(u\). Thereafter \(v\)'s subtree is completely printed and \((u, v)\) is never crossed again.
  • If \(v\) is \(u\)'s right child: after printing \(u\), TREE-SUCCESSOR(u) traverses \((u, v)\) downward to find the minimum of \(v\)'s subtree; after all nodes of \(v\)'s subtree are printed, TREE-SUCCESSOR traverses \((u, v)\) upward once on its way to an ancestor after \(u\), and never again.

No edge is traversed twice in the same direction, so total time is \(\Theta(n)\).

Exercise 12.3-3

TREE-SORT: tempo nel caso peggiore e migliore

You can sort a given set of \(n\) numbers by first building a binary search tree containing these numbers (using TREE-INSERT repeatedly to insert the numbers one by one) and then printing the numbers by an inorder tree walk. What are the worst-case and best-case running times for this sorting algorithm?

Mostra soluzione ufficiale (Cormen, p. 12-2) 
TREE-SORT(A)
let T be an empty binary search tree
for i = 1 to n
    TREE-INSERT(T, A[i])
INORDER-TREE-WALK(T.root)
  • Worst case: \(\Theta(n^2)\), which occurs when repeated TREE-INSERT operations produce a linear chain of height \(n - 1\) (e.g. already sorted input).
  • Best case: \(\Theta(n \lg n)\), which occurs when repeated TREE-INSERT operations produce a balanced binary tree of height \(\Theta(\lg n)\).

Problem 12-2

Radix Trees: ordinamento lessicografico di stringhe binarie in \(\Theta(n)\)

Given two strings \(a = a_0 a_1 \dots a_p\) and \(b = b_0 b_1 \dots b_q\), where each \(a_i\) and each \(b_j\) is in some ordered set of characters, we say that string \(a\) is lexicographically less than string \(b\) if either:

  1. there exists an integer \(j\) (\(0 \le j \le \min(p, q)\)) such that \(a_i = b_i\) for all \(i = 0, 1, \dots, j - 1\) and \(a_j < b_j\), or
  2. \(p < q\) and \(a_i = b_i\) for all \(i = 0, 1, \dots, p\).

A radix tree stores bit strings by going left at depth \(i\) if \(a_i = 0\) and right if \(a_i = 1\). Let \(S\) be a set of distinct bit strings whose lengths sum to \(n\). Show how to use a radix tree to sort \(S\) lexicographically in \(\Theta(n)\) time. For the set \(\{1011, 10, 011, 100, 0\}\), the output should be \(0, 011, 10, 100, 1011\).

Mostra soluzione ufficiale (Cormen, p. 12-3 / 12-4)

Insert all strings of \(S\) into a radix tree, marking each terminal node with x.string = TRUE, then extract them via a preorder tree walk, printing only marked nodes.

Correctness:

  • Any node's string is a prefix of all its descendants' strings, so printing the node before its subtrees satisfies rule 2.
  • All strings in the left subtree share the parent's prefix followed by \(0\), whereas those in the right subtree have \(1\) in that position, so visiting left before right satisfies rule 1.

Time \(\Theta(n)\): Inserting each string takes time proportional to its length, summing to \(\Theta(n)\). The tree has at most \(1 + n\) nodes, so the preorder traversal takes \(O(n)\) time. Initial call: PREORDER-RADIX-TREE-WALK(T.root, ε).

PREORDER-RADIX-TREE-WALK(x, string-so-far)
if x.string == TRUE
    print string-so-far
if x.left != NIL
    PREORDER-RADIX-TREE-WALK(x.left, string-so-far || 0)

Chapter 20: Elementary Graph Algorithms (Lect. 7, 8)

Exercise 20.1-7

Matrice di incidenza \(B\) di un grafo diretto: significato di \(B B^T\)

The incidence matrix of a directed graph \(G = (V, E)\) with no self-loops is a \(|V| \times |E|\) matrix \(B = (b_{ij})\) such that

\[ b_{ij} = \begin{cases} -1 & \text{if edge } j \text{ leaves vertex } i, \\ 1 & \text{if edge } j \text{ enters vertex } i, \\ 0 & \text{otherwise.} \end{cases} \]

Describe what the entries of the matrix product \(B B^T\) represent, where \(B^T\) is the transpose of \(B\).

Mostra soluzione ufficiale (Cormen, p. 20-1)
\[ (B B^T)(i, j) = \sum_{e \in E} b_{ie} b^T_{ej} = \sum_{e \in E} b_{ie} b_{je} \]
  • If \(i = j\), then \(b_{ie} b_{je} = 1\) (either \(1 \cdot 1\) or \((-1)(-1)\)) whenever edge \(e\) enters or leaves vertex \(i\), and \(0\) otherwise.
  • If \(i \ne j\), then \(b_{ie} b_{je} = -1\) whenever \(e = (i, j)\) or \(e = (j, i)\), and \(0\) otherwise.
\[ (B B^T)(i, j) = \begin{cases} \text{in-degree}(i) + \text{out-degree}(i) & \text{if } i = j, \\ -(\text{number of edges connecting } i \text{ and } j) & \text{if } i \ne j. \end{cases} \]
Exercise 20.2-5

BFS: indipendenza di \(u.d\) e dipendenza dell'albero dall'ordine delle liste di adiacenza

Argue that in a breadth-first search, the value \(u.d\) assigned to a vertex \(u\) is independent of the order in which the vertices appear in each adjacency list. Using Figure 20.3 (3rd ed.: Figure 22.3) as an example, show that the breadth-first tree computed by BFS can depend on the ordering within adjacency lists.

Mostra soluzione ufficiale (Cormen, p. 20-1)

The correctness proof for BFS proves that \(u.d = \delta(s, u)\) upon termination, without assuming any particular ordering of the adjacency lists. Because \(\delta(s, u)\) depends only on the graph itself, \(u.d\) is independent of the adjacency-list orderings.

However, the breadth-first tree can change: in Figure 20.3, if \(t\) precedes \(x\) in \(Adj[w]\), we obtain the breadth-first tree shown in the figure (where \(u\) is discovered from \(t\)). If instead \(x\) precedes \(t\) in \(Adj[w]\) and \(u\) precedes \(y\) in \(Adj[x]\), then edge \((x, u)\) becomes part of the breadth-first tree.

Problem 20-1

Classificazione degli archi tramite BFS (grafi non orientati e orientati)

A breadth-first tree can be used to classify the edges reachable from the source of the search into tree, back, forward, and cross edges.

  1. Prove that in a breadth-first search of an undirected graph:
    1. There are no back edges and no forward edges.
    2. For each tree edge \((u, v)\), \(v.d = u.d + 1\).
    3. For each cross edge \((u, v)\), \(v.d = u.d\) or \(v.d = u.d + 1\).
  2. Prove that in a breadth-first search of a directed graph:
    1. There are no forward edges.
    2. For each tree edge \((u, v)\), \(v.d = u.d + 1\).
    3. For each cross edge \((u, v)\), \(v.d \le u.d + 1\).
    4. For each back edge \((u, v)\), \(0 \le v.d \le u.d\).
Mostra soluzione ufficiale (Cormen, p. 20-3)

a. Undirected graph:

  1. Suppose \((u, v)\) is a back or forward edge; WLOG let \(u\) be a proper ancestor of \(v\) in the breadth-first tree. Because all edges incident on \(u\) are explored before any edges of \(u\)'s descendants, \((u, v)\) must be explored from \(u\) while \(v\) is still white, making \((u, v)\) a tree edge.
  2. An edge \((u, v)\) becomes a tree edge precisely when BFS sets \(v.\pi = u\) and \(v.d = u.d + 1\). Neither \(u.d\) nor \(v.d\) changes afterward.
  3. For a cross edge \((u, v)\) with \(u\) visited before \(v\), when \(u\)'s edges are explored \(v\) must already be on the queue (else \((u, v)\) would be a tree edge). By Lemma 20.3 \(v.d \le u.d + 1\), and by Corollary 20.4 \(v.d \ge u.d\). Hence \(v.d = u.d\) or \(v.d = u.d + 1\).

b. Directed graph:

  1. If \((u, v)\) were a forward edge, it would have been explored while scanning \(u\)'s adjacency list before reaching any descendant of \(u\), so it would be a tree edge.
  2. Same proof as part (a.2).
  3. For any edge \((u, v)\), \(v\) is discovered at the latest when \((u, v)\) is explored, so \(v.d \le u.d + 1\).
  4. Clearly \(v.d \ge 0\). For a back edge \((u, v)\), \(v\) is an ancestor of \(u\) in the breadth-first tree (including \(u = v\) for self-loops), so \(v.d \le u.d\).

Chapter 22: Single-Source Shortest Paths (Dijkstra) (Lect. 8)

Exercise 22.3-3

Dijkstra con ciclo while |Q| > 1 (\(|V| - 1\) iterazioni)

Suppose we change line 4 of Dijkstra's algorithm to the following:

4  while |Q| > 1

This change causes the while loop to execute \(|V| - 1\) times instead of \(|V|\) times. Is this proposed algorithm correct?

Mostra soluzione ufficiale (Cormen, p. 22-2)

Yes, the algorithm still works. Let \(u\) be the leftover vertex that is not extracted from the priority queue \(Q\).

  • If \(u\) is not reachable from \(s\), then \(u.d = \delta(s, u) = \infty\).
  • If \(u\) is reachable from \(s\), there is a shortest path \(p = s \leadsto x \to u\). Because \(x\) was already extracted earlier, at that moment \(x.d = \delta(s, x)\) and the edge \((x, u)\) was relaxed; therefore \(u.d = \delta(s, u)\).
Exercise 22.3-7

Cammino piu affidabile (Most Reliable Path) con Dijkstra

We are given a directed graph \(G = (V, E)\) on which each edge \((u, v) \in E\) has an associated value \(r(u, v)\), which is a real number in the range \(0 \le r(u, v) \le 1\) that represents the reliability of a communication channel from vertex \(u\) to vertex \(v\). We interpret \(r(u, v)\) as the probability that the channel from \(u\) to \(v\) will not fail, and we assume that these probabilities are independent. Give an efficient algorithm to find the most reliable path between two given vertices \(s\) and \(t\).

Mostra soluzione ufficiale (Cormen, p. 22-2 / 22-3)

Method 1 (logarithmic weights + standard Dijkstra): Because edge reliabilities are independent, we want a path \(p\) from \(s\) to \(t\) maximizing \(\prod_{(u,v) \in p} r(u, v)\). Taking logarithms, this is equivalent to maximizing \(\sum_{(u,v) \in p} \lg r(u, v)\), i.e. minimizing \(\sum_{(u,v) \in p} (-\lg r(u, v))\).

Assign edge weights \(w(u, v) = -\lg r(u, v)\) (with \(\lg 0 = -\infty\), so \(w = +\infty\) when \(r = 0\)). Since \(0 \le r(u, v) \le 1\), we have \(\lg r(u, v) \le 0\), so all weights \(w(u, v) \ge 0\). Run Dijkstra's algorithm from \(s\) in \(O(E + V \lg V)\) time (or \(O((V + E)\lg V)\) with a binary heap).

Method 2 (modified Dijkstra directly on probabilities):

  • Initialize \(v.d = 0\) (or \(-\infty\)) for \(v \ne s\) and \(s.d = 1\).
  • Use a max-priority queue \(Q\) with EXTRACT-MAX(Q) and INCREASE-KEY(Q, v, v.d).
  • Modify relaxation to multiply reliabilities:
RELAX(u, v, r)
if v.d < u.d * r(u, v)
    v.d = u.d * r(u, v)
    v.pi = u
